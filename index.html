A portable language for describing programs.

PSI is a small intermediate representation designed to provide a simple and portable foundation for compilers and systems programming.

What is PSI?

PSI is an intermediate representation that sits between a programming language and machine code. It provides a common way to describe programs while allowing compilers to target different architectures.

Instead of tying a language directly to a particular CPU, PSI acts as a portable layer between the language and the target machine.

example.psi 
// A simple function that adds two numbers
func i32 add i32 a i32 b {
    i32 result = add a b;
    ret result;
}

// Entry point of the program
entry main {
    i32 x = 10;
    i32 y = 20;
    i32 sum = call add x y;

    // System call to write output (Linux x86_64)
    i64 fd = 1;              // stdout
    i64* msg = "Sum: ";
    i64 len = 5;
    #syscall 1 fd msg len;

    ret;
}

Simple by design.

PSI is designed to stay close to the machine without becoming tied to one architecture. Its instructions describe the operations a program needs while leaving architecture-specific details to the compiler backend.

🎯 Portable

One representation that works across x86, x86-64, ARM, and AArch64.

⚡ Low-level

Direct access to registers, memory, and system calls when needed.

🔧 Extensible

Special instructions and registers for architecture-specific features.

📦 Simple

Small instruction set with clear semantics and no hidden complexity.

PSI in action.

Here are some examples showing PSI's features, from basic arithmetic to structs, arrays, and inline assembly.

struct.psi 
// Define a struct with alignment
struct Point : 8 {
    i32 x;
    i32 y;
};

// Function that works with structs
func i32 manhattan_distance Point* p1 Point* p2 {
    i32 dx = sub p1.x p2.x;
    i32 dy = sub p1.y p2.y;
    i32 abs_dx = dx;
    i32 abs_dy = dy;

    // Absolute value using conditional logic
    cjmp lt dx 0 neg_dx;
    jmp after_dx;
    label neg_dx:
    abs_dx = neg dx;
    label after_dx:

    cjmp lt dy 0 neg_dy;
    jmp after_dy;
    label neg_dy:
    abs_dy = neg dy;
    label after_dy:

    ret add abs_dx abs_dy;
}
array.psi 
// Arrays and pointers
entry main {
    i32* numbers = [10, 20, 30, 40, 50];

    i32 sum = 0;
    i32 i = 0;

    label loop:
    cjmp ge i 5 done;
    i32* ptr = ref numbers[i];
    i32 val = load ptr;
    sum = add sum val;
    i = add i 1;
    jmp loop;

    label done:
        // Store the result
    i32* result_ptr = ref sum;
    store result_ptr sum;

    ret;
}
special.psi 
// Special registers and instructions
entry main {
    // Read the current cycle counter (x86 only)
    i64 cycles = #rdtsc;

    // Use x86_64 specific registers directly
    %rax = 42;
    %rbx = 100;
    i64 result = add %rax %rbx;

    // Floating point operations
    f32 a = 3.14;
    f32 b = 2.71;
    f32 c = #fadd a b;

    // Atomic operations
    i32 counter = 0;
    i32* counter_ptr = ref counter;
    i32 old = #atomic_add counter_ptr 1;

    // Memory barrier
    #fence;

    ret;
}
