A small, C‑like, architecture‑aware language.

PSI (Portable System Interface) gives you direct access to hardware registers and instructions without hand‑writing assembly for every platform. Write once, compile to x86, x86‑64, ARM, and AArch64.

📄 Read Specs v0.1

What is PSI?

PSI is a tiny, portable language designed for systems programming where you need fine‑grained control over the machine. It provides a familiar C‑like syntax while exposing architecture‑specific features through special registers (%rax) and special instructions (#syscall).

The language has a small set of ordinary instructions (add, call, jmp, …) that work the same everywhere. For everything else, you use the target‑specific # and % forms, visually marking where your code becomes platform‑dependent.

example.psi 
// A simple function that adds two integers
func i32 add i32 a i32 b {
    i32 result = add a b;
    ret result;
}

// Entry point – the symbol "main" is emitted exactly as declared
entry main {
    i32 x = 10;
    i32 y = 20;
    i32 sum = call add x y;

    // Write "Sum: " to stdout using Linux syscall (x86_64)
    i64 fd = 1;              // stdout
    i8* msg = "Sum: ";
    i64 len = 5;
    #syscall 1 fd msg len;   // write(fd, msg, len)

    // Exit with code 0
    #syscall 60 0;           // exit(0)
}

Designed for portability and control.

PSI stays close to the machine without being tied to one CPU. The compiler (psic) handles target‑specific calling conventions, register allocation, and instruction selection — you just write logic in a clean, portable language.

🎯 Portable

One language works across x86, x86‑64, ARM, and AArch64.

⚡ Low‑level

Read/write physical registers, issue system calls, and use memory barriers directly.

🔧 Extensible

Special instructions (#) give you access to hardware features like rdtsc, popcnt, and FPU ops.

📦 Simple

A minimal set of types (integers, floats, pointers, structs) and a handful of ordinary instructions — no hidden magic.

More examples

The GitHub repository contains the full specification and a growing set of real‑world examples, including:

  • Fibonacci and factorial functions
  • Simple string manipulation
  • Direct memory access with pointer arithmetic
  • Using #fence for synchronization
  • Counting leading/trailing zero bits with #clz and #ctz

The compiler psic is built on LLVM, but the specification is backend‑agnostic — any conforming implementation must produce the same observable behavior.
